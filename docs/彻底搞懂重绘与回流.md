## 简介

在前端性能优化中，**回流（Reflow）**和**重绘（Repaint）**是两个核心概念。理解它们的区别和触发机制，对于编写高性能的 Web 应用至关重要。

### 为什么需要关注？

- ⚡ **性能瓶颈**：频繁的回流和重绘会导致页面卡顿
- 📱 **移动端敏感**：移动设备性能有限，更需要优化
- 🎯 **用户体验**：流畅的动画和交互依赖良好的渲染性能
- 💰 **业务价值**：性能直接影响用户留存和转化率

### 关键数据

```
回流成本 >> 重绘成本 >> JavaScript 执行成本

一次回流可能触发：
- 布局计算（Layout）
- 几何属性重新计算
- 子元素级联更新
- 最终触发重绘

典型耗时：
- 简单重绘：1-5ms
- 复杂回流：16-100ms+
- 目标帧率：60fps（每帧 16.67ms）
```

## 浏览器渲染流程

要理解回流和重绘，首先需要了解浏览器的完整渲染流程：

```
HTML 解析          CSS 解析           JavaScript 执行
    ↓                  ↓                    ↓
DOM Tree  ←────→  CSSOM Tree              ↓
    ↓                  ↓                    ↓
    └────→  Render Tree (渲染树) ←─────────┘
                ↓
            Layout (布局/回流)
                ↓
            Paint (绘制/重绘)
                ↓
            Composite (合成)
                ↓
            Display (显示到屏幕)
```

### 详细流程说明

#### 1. 构建 DOM 树

```html
<!-- HTML -->
<html>
  <head>
    <title>示例</title>
  </head>
  <body>
    <div class="container">
      <h1>标题</h1>
      <p>段落</p>
    </div>
  </body>
</html>
```

浏览器解析后生成 DOM 树：

```
Document
├── html
│   ├── head
│   │   └── title
│   └── body
│       └── div.container
│           ├── h1
│           └── p
```

#### 2. 构建 CSSOM 树

```css
/* CSS */
.container {
  width: 800px;
  padding: 20px;
}

h1 {
  font-size: 24px;
  color: #333;
}
```

生成 CSSOM 树，包含所有样式信息。

#### 3. 生成 Render Tree

将 DOM 和 CSSOM 合并，生成渲染树（排除 `display: none` 的元素）：

```
Render Tree
├── html
│   └── body
│       └── div.container (width: 800px, padding: 20px)
│           ├── h1 (font-size: 24px, color: #333)
│           └── p
```

#### 4. Layout（布局/回流）

计算每个节点的**几何信息**：
- 位置（x, y 坐标）
- 尺寸（width, height）
- 边距、边框、内边距

#### 5. Paint（绘制/重绘）

将渲染树转换为屏幕上的**像素**：
- 填充颜色
- 绘制文本
- 绘制图片
- 绘制边框

#### 6. Composite（合成）

将多个图层合成为最终图像，利用 GPU 加速。

## 什么是回流（Reflow）？

### 定义

**回流（Reflow）**，也称为**布局（Layout）**，是指浏览器重新计算元素的几何属性（位置和尺寸），并重新构建渲染树的过程。

### 核心特征

- 🔴 **成本高**：需要重新计算布局
- 🔴 **影响范围广**：可能触发子元素甚至整个页面的重新布局
- 🔴 **阻塞渲染**：同步执行，阻塞后续操作

### 触发回流的场景

#### 1. 添加或删除可见的 DOM 元素

```javascript
// ❌ 触发回流
document.body.appendChild(newElement);
element.remove();

// ✅ 优化：使用 DocumentFragment
const fragment = document.createDocumentFragment();
for (let i = 0; i < 100; i++) {
  const div = document.createElement('div');
  div.textContent = `Item ${i}`;
  fragment.appendChild(div);
}
document.body.appendChild(fragment); // 只触发一次回流
```

#### 2. 改变元素尺寸

```javascript
// ❌ 触发回流
element.style.width = '200px';
element.style.height = '100px';
element.style.padding = '10px';
element.style.margin = '5px';
element.style.border = '1px solid black';
```

#### 3. 改变元素位置

```javascript
// ❌ 触发回流
element.style.top = '100px';
element.style.left = '50px';
element.style.position = 'absolute';
```

#### 4. 改变字体大小或内容

```javascript
// ❌ 触发回流
element.style.fontSize = '20px';
element.textContent = '新的更长的文本内容';
```

#### 5. 激活 CSS 伪类

```css
/* ❌ hover 时可能触发回流 */
.element:hover {
  width: 200px; /* 改变尺寸 */
}

/* ✅ 只触发重绘 */
.element:hover {
  color: red; /* 只改变颜色 */
}
```

#### 6. 读取某些属性（强制同步布局）

```javascript
// ❌ 读取这些属性会触发立即回流
const width = element.offsetWidth;
const height = element.offsetHeight;
const top = element.offsetTop;
const left = element.offsetLeft;
const clientWidth = element.clientWidth;
const scrollWidth = element.scrollWidth;

// 浏览器必须先完成布局计算才能返回这些值
```

#### 7. 窗口大小改变

```javascript
// ❌ 触发整个页面的回流
window.addEventListener('resize', () => {
  // 页面重新布局
});
```

### 回流的影响范围

```
单个元素回流可能的传播路径：

1. 自身回流
   element.style.width = '200px';

2. 子元素回流（级联）
   parent.style.width = '500px';
   // 所有子元素可能需要重新计算位置

3. 兄弟元素回流
   element.style.position = 'absolute';
   // 后续元素位置可能改变

4. 父元素回流
   child.style.width = '100%';
   // 父元素需要重新计算

5. 全局回流（最严重）
   document.body.style.fontSize = '20px';
   // 整个页面重新布局
```

## 什么是重绘（Repaint）？

### 定义

**重绘（Repaint）**，也称为** redraw**，是指浏览器重新绘制元素的视觉表现，但不改变其几何属性（位置和尺寸）。

### 核心特征

- 🟡 **成本较低**：只需重新绘制像素
- 🟡 **影响范围小**：仅影响当前元素
- 🟡 **不触发布局**：跳过 Layout 阶段

### 触发重绘的场景

#### 1. 改变颜色相关属性

```javascript
// ✅ 只触发重绘
element.style.color = 'red';
element.style.backgroundColor = 'blue';
element.style.borderColor = 'green';
element.style.boxShadow = '0 0 10px rgba(0,0,0,0.5)';
```

#### 2. 改变可见性（不改变布局）

```javascript
// ✅ 只触发重绘
element.style.visibility = 'hidden'; // 占据空间但不可见
element.style.opacity = '0.5';
```

#### 3. 改变背景图片

```javascript
// ✅ 只触发重绘
element.style.backgroundImage = 'url(new-image.jpg)';
```

#### 4. 改变 outline

```javascript
// ✅ 只触发重绘
element.style.outline = '2px solid red';
```

### 重绘 vs 不回溯

```javascript
// ❌ visibility: hidden - 触发重绘
element.style.visibility = 'hidden';

// ✅ display: none - 触发回流 + 重绘
element.style.display = 'none';
// 元素从渲染树中移除，影响布局
```

## 触发条件对比

### 对比表格

| 操作 | 回流 | 重绘 | 说明 |
|------|------|------|------|
| 改变 `width/height` | ✅ | ✅ | 先回流再重绘 |
| 改变 `margin/padding` | ✅ | ✅ | 先回流再重绘 |
| 改变 `position/top/left` | ✅ | ✅ | 先回流再重绘 |
| 改变 `color/background` | ❌ | ✅ | 只重绘 |
| 改变 `visibility` | ❌ | ✅ | 只重绘 |
| 改变 `opacity` | ❌ | ✅ | 只重绘（GPU 加速） |
| 改变 `transform` | ❌ | ❌ | 只合成（最优） |
| 添加/删除 DOM | ✅ | ✅ | 先回流再重绘 |
| 读取布局属性 | ✅ | - | 强制同步回流 |
| 窗口 resize | ✅ | ✅ | 全局回流 |

### 代码示例对比

```javascript
const element = document.getElementById('box');

// ========== 触发回流的操作 ==========

// 1. 改变尺寸
element.style.width = '200px';        // ✅ 回流 + 重绘
element.style.height = '100px';       // ✅ 回流 + 重绘

// 2. 改变位置
element.style.top = '50px';           // ✅ 回流 + 重绘
element.style.left = '100px';         // ✅ 回流 + 重绘

// 3. 改变盒模型
element.style.margin = '10px';        // ✅ 回流 + 重绘
element.style.padding = '5px';        // ✅ 回流 + 重绘
element.style.border = '1px solid';   // ✅ 回流 + 重绘

// 4. 改变字体
element.style.fontSize = '20px';      // ✅ 回流 + 重绘

// 5. 添加/删除元素
const newDiv = document.createElement('div');
document.body.appendChild(newDiv);    // ✅ 回流 + 重绘

// 6. 读取布局属性（强制同步回流）
console.log(element.offsetWidth);     // ✅ 立即回流


// ========== 只触发重绘的操作 ==========

// 1. 改变颜色
element.style.color = 'red';          // ❌ 只重绘
element.style.backgroundColor = 'blue'; // ❌ 只重绘

// 2. 改变透明度
element.style.opacity = '0.5';        // ❌ 只重绘

// 3. 改变可见性
element.style.visibility = 'hidden';  // ❌ 只重绘

// 4. 改变阴影
element.style.boxShadow = '0 0 10px black'; // ❌ 只重绘


// ========== 不触发回流也不触发重绘（最优）==========

// 1. 使用 transform
element.style.transform = 'translate(100px, 50px)';  // ✅ 只合成
element.style.transform = 'scale(1.5)';              // ✅ 只合成
element.style.transform = 'rotate(45deg)';           // ✅ 只合成

// 2. 使用 opacity（配合 will-change）
element.style.willChange = 'opacity';
element.style.opacity = '0';                          // ✅ GPU 加速
```

## 性能影响分析

### 性能成本对比

```
性能开销排序（从高到低）：

1. 全局回流（Window Resize）
   └─ 耗时：50-200ms+
   └─ 影响：整个页面

2. 复杂元素回流（嵌套深、子元素多）
   └─ 耗时：20-100ms
   └─ 影响：元素及其子树

3. 简单元素回流
   └─ 耗时：5-20ms
   └─ 影响：单个元素

4. 重绘
   └─ 耗时：1-5ms
   └─ 影响：单个元素

5. 合成（Composite）
   └─ 耗时：<1ms
   └─ 影响：GPU 处理，几乎无 CPU 开销

目标：保持每帧 < 16.67ms（60fps）
```

### 实际测试示例

```javascript
// 性能测试：回流 vs 重绘
function testPerformance() {
  const element = document.getElementById('test');
  
  // 测试回流
  console.time('Reflow');
  for (let i = 0; i < 1000; i++) {
    element.style.width = `${100 + i}px`;
  }
  console.timeEnd('Reflow'); // 约 50-100ms
  
  // 测试重绘
  console.time('Repaint');
  for (let i = 0; i < 1000; i++) {
    element.style.backgroundColor = `rgb(${i}, 0, 0)`;
  }
  console.timeEnd('Repaint'); // 约 10-20ms
  
  // 测试合成
  console.time('Composite');
  for (let i = 0; i < 1000; i++) {
    element.style.transform = `translateX(${i}px)`;
  }
  console.timeEnd('Composite'); // 约 1-5ms
}
```

### 帧率影响

```javascript
// 60fps = 每帧 16.67ms
// 30fps = 每帧 33.33ms（可接受的最低标准）

// ❌ 糟糕的性能：每次操作触发回流
function badAnimation() {
  let pos = 0;
  setInterval(() => {
    element.style.left = pos++ + 'px'; // 触发回流
  }, 16); // 期望 60fps，实际可能只有 10-20fps
}

// ✅ 良好的性能：使用 transform
function goodAnimation() {
  let pos = 0;
  function animate() {
    element.style.transform = `translateX(${pos++}px)`; // 只合成
    requestAnimationFrame(animate);
  }
  animate(); // 稳定 60fps
}
```

## 如何检测回流和重绘？

### 方法 1：Chrome DevTools Performance 面板

```
步骤：
1. 打开 Chrome DevTools (F12)
2. 切换到 Performance 面板
3. 点击录制按钮（●）
4. 执行操作
5. 停止录制
6. 查看 Events 中的：
   - Layout（回流）
   - Paint（重绘）
   - Composite Layers（合成）
```

**识别标志：**
- 🔴 红色区域：回流（Layout）
- 🟡 黄色区域：重绘（Paint）
- 🟢 绿色区域：合成（Composite）

### 方法 2：使用 Performance API

```javascript
// 监控长任务
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.duration > 50) { // 超过 50ms 的长任务
      console.warn('长任务 detected:', entry);
    }
  }
});

observer.observe({ entryTypes: ['longtask'] });
```

### 方法 3：强制同步布局检测

```javascript
// 检测强制同步布局警告
// 在 Console 中会出现黄色警告：
// "Warning: Forced reflow is a likely performance bottleneck"

// 常见触发代码：
element.offsetWidth;  // 读取前修改了样式
element.style.width = '100px';
const width = element.offsetWidth; // ⚠️ 强制同步回流
```

### 方法 4：使用第三方工具

```javascript
// why-did-you-render (React)
import whyDidYouRender from '@welldone-software/why-did-you-render';
whyDidYouRender(React, {
  trackAllPureComponents: true,
});

// 检测不必要的重渲染
```

## 优化策略与最佳实践

### 策略 1：最小化回流次数

#### ❌ 错误做法：多次触发回流

```javascript
const element = document.getElementById('box');

// 每次赋值都触发回流
element.style.width = '100px';    // 回流 1
element.style.height = '200px';   // 回流 2
element.style.margin = '10px';    // 回流 3
element.style.padding = '5px';    // 回流 4
```

#### ✅ 优化方案 1：批量修改

```javascript
const element = document.getElementById('box');

// 使用 cssText 一次性修改
element.style.cssText = `
  width: 100px;
  height: 200px;
  margin: 10px;
  padding: 5px;
`; // 只触发 1 次回流
```

#### ✅ 优化方案 2：使用 class

```css
/* CSS */
.new-style {
  width: 100px;
  height: 200px;
  margin: 10px;
  padding: 5px;
}
```

```javascript
// JavaScript
element.className = 'new-style'; // 只触发 1 次回流
```

#### ✅ 优化方案 3：使用 DocumentFragment

```javascript
// ❌ 逐个添加，触发多次回流
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  ul.appendChild(li); // 每次都回流
}

// ✅ 使用 DocumentFragment，只触发一次回流
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);
}
ul.appendChild(fragment); // 只回流一次
```

### 策略 2：避免强制同步布局

#### ❌ 错误做法：读写交替

```javascript
const elements = document.querySelectorAll('.item');

elements.forEach(el => {
  el.style.width = '100px';           // 写
  const width = el.offsetWidth;       // 读 - 强制同步回流！
  el.style.height = width + 'px';     // 写
});
```

#### ✅ 优化方案：先读后写

```javascript
const elements = document.querySelectorAll('.item');

// 第一步：读取所有需要的值
const widths = Array.from(elements).map(el => el.offsetWidth);

// 第二步：批量写入
elements.forEach((el, index) => {
  el.style.width = '100px';
  el.style.height = widths[index] + 'px';
});
```

### 策略 3：使用 transform 和 opacity

#### ❌ 错误做法：使用 top/left 动画

```css
/* ❌ 触发回流 */
@keyframes slide {
  from {
    left: 0;
  }
  to {
    left: 100px;
  }
}

.element {
  position: absolute;
  animation: slide 1s ease-in-out;
}
```

#### ✅ 优化方案：使用 transform

```css
/* ✅ 只触发合成，GPU 加速 */
@keyframes slide {
  from {
    transform: translateX(0);
  }
  to {
    transform: translateX(100px);
  }
}

.element {
  animation: slide 1s ease-in-out;
  will-change: transform; /* 提示浏览器优化 */
}
```

### 策略 4：脱离文档流

```css
/* ✅ 绝对定位元素变化不会影响其他元素 */
.popup {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

/* ✅ 改变 popup 的尺寸不会导致页面其他部分回流 */
```

### 策略 5：使用虚拟滚动

```javascript
// ❌ 渲染大量 DOM 元素
function BadList({ items }) {
  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}

// ✅ 使用虚拟滚动（只渲染可视区域）
import { FixedSizeList } from 'react-window';

function GoodList({ items }) {
  return (
    <FixedSizeList
      height={400}
      itemCount={items.length}
      itemSize={50}
      width="100%"
    >
      {({ index, style }) => (
        <li style={style}>{items[index].name}</li>
      )}
    </FixedSizeList>
  );
}
```

### 策略 6：防抖和节流

```javascript
// ❌ resize 事件频繁触发回流
window.addEventListener('resize', () => {
  updateLayout(); // 每次 resize 都执行
});

// ✅ 使用防抖
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

window.addEventListener('resize', debounce(() => {
  updateLayout();
}, 200)); // 200ms 内只执行一次
```

### 策略 7：使用 will-change

```css
/* 提示浏览器提前优化 */
.animated-element {
  will-change: transform, opacity;
}

/* 
注意：
1. 不要滥用 will-change
2. 使用后记得移除
3. 适用于即将发生变化的元素
*/
```

```javascript
// 动态管理 will-change
element.style.willChange = 'transform';

// 动画结束后移除
element.addEventListener('transitionend', () => {
  element.style.willChange = 'auto';
});
```

### 策略 8：分层渲染（Layer Promotion）

```css
/* 创建独立的合成层 */
.layer {
  transform: translateZ(0); /* 触发 GPU 加速 */
  /* 或 */
  will-change: transform;
}

/* 
优点：
- 独立图层，变化不影响其他元素
- GPU 处理，性能更好

缺点：
- 占用更多内存
- 过多图层反而降低性能
*/
```

## 实战案例

### 案例 1：高性能列表渲染

```tsx
import React, { useMemo } from 'react';

interface Item {
  id: number;
  name: string;
}

// ❌ 低效实现
function BadList({ items }: { items: Item[] }) {
  return (
    <ul>
      {items.map(item => (
        <li 
          key={item.id}
          style={{
            padding: '10px',
            borderBottom: '1px solid #eee'
          }}
        >
          {item.name}
        </li>
      ))}
    </ul>
  );
}

// ✅ 高效实现
function GoodList({ items }: { items: Item[] }) {
  // 使用 CSS class 而非 inline styles
  // 减少样式计算和回流
  
  const listItems = useMemo(() => 
    items.map(item => (
      <li key={item.id} className="list-item">
        {item.name}
      </li>
    )),
    [items]
  );

  return <ul className="optimized-list">{listItems}</ul>;
}
```

```css
/* CSS */
.optimized-list {
  list-style: none;
  padding: 0;
  margin: 0;
}

.list-item {
  padding: 10px;
  border-bottom: 1px solid #eee;
  /* 避免使用会影响布局的属性 */
}
```

### 案例 3：优化表格排序

```tsx
import React, { useState, useMemo } from 'react';

interface User {
  id: number;
  name: string;
  age: number;
}

// ❌ 每次排序都重新渲染所有行
function BadTable({ users }: { users: User[] }) {
  const [sortedUsers, setSortedUsers] = useState(users);

  const handleSort = (key: keyof User) => {
    const sorted = [...sortedUsers].sort((a, b) => {
      if (a[key] < b[key]) return -1;
      if (a[key] > b[key]) return 1;
      return 0;
    });
    setSortedUsers(sorted); // 触发所有行重渲染
  };

  return (
    <table>
      <thead>
        <tr>
          <th onClick={() => handleSort('name')}>姓名</th>
          <th onClick={() => handleSort('age')}>年龄</th>
        </tr>
      </thead>
      <tbody>
        {sortedUsers.map(user => (
          <tr key={user.id}> {/* 没有稳定的 key */}
            <td>{user.name}</td>
            <td>{user.age}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

// ✅ 使用 React.memo 和稳定 key
const TableRow = React.memo(({ user }: { user: User }) => (
  <tr>
    <td>{user.name}</td>
    <td>{user.age}</td>
  </tr>
));

function GoodTable({ users }: { users: User[] }) {
  const [sortKey, setSortKey] = useState<keyof User>('name');

  // 使用 useMemo 缓存排序结果
  const sortedUsers = useMemo(() => {
    return [...users].sort((a, b) => {
      if (a[sortKey] < b[sortKey]) return -1;
      if (a[sortKey] > b[sortKey]) return 1;
      return 0;
    });
  }, [users, sortKey]);

  const handleSort = (key: keyof User) => {
    setSortKey(key);
  };

  return (
    <table>
      <thead>
        <tr>
          <th onClick={() => handleSort('name')}>姓名</th>
          <th onClick={() => handleSort('age')}>年龄</th>
        </tr>
      </thead>
      <tbody>
        {sortedUsers.map(user => (
          <TableRow key={user.id} user={user} /> {/* 稳定 key + memo */}
        ))}
      </tbody>
    </table>
  );
}
```

### 案例 4：图片懒加载优化

```tsx
import React, { useEffect, useRef, useState } from 'react';

interface LazyImageProps {
  src: string;
  alt: string;
  width: number;
  height: number;
}

// ✅ 使用 Intersection Observer 实现懒加载
function LazyImage({ src, alt, width, height }: LazyImageProps) {
  const [isLoaded, setIsLoaded] = useState(false);
  const imgRef = useRef<HTMLImageElement>(null);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setIsLoaded(true);
          observer.disconnect();
        }
      },
      { rootMargin: '50px' } // 提前 50px 开始加载
    );

    if (imgRef.current) {
      observer.observe(imgRef.current);
    }

    return () => observer.disconnect();
  }, []);

  return (
    <div 
      ref={imgRef}
      style={{ 
        width, 
        height,
        backgroundColor: '#f0f0f0' // 占位背景
      }}
    >
      {isLoaded && (
        <img
          src={src}
          alt={alt}
          style={{
            width: '100%',
            height: '100%',
            objectFit: 'cover',
            opacity: 0,
            animation: 'fadeIn 0.3s forwards'
          }}
          onLoad={(e) => {
            // 图片加载完成后显示
            (e.target as HTMLImageElement).style.opacity = '1';
          }}
        />
      )}
    </div>
  );
}
```

  to {
    opacity: 1;
  }
}

## 常见误区

### 误区 1：认为 display: none 比 visibility: hidden 性能好

```javascript
// ❌ 错误认知
element.style.display = 'none'; // 以为这样更快

// ✅ 实际情况
// display: none - 触发回流 + 重绘（从渲染树移除）
// visibility: hidden - 只触发重绘（仍在渲染树中）

// 选择建议：
// - 需要保留空间：用 visibility: hidden
// - 不需要保留空间：用 display: none
// - 频繁切换：考虑 opacity + pointer-events
```

### 误区 2：过度使用 will-change

```css
/* ❌ 滥用 will-change */
* {
  will-change: transform;
}

/* 
问题：
1. 占用大量内存
2. 浏览器优化失效
3. 可能导致性能下降
*/

/* ✅ 正确使用 */
.animated-element {
  /* 只在动画前设置 */
}

/* 动画结束后移除 */
.animated-element.finished {
  will-change: auto;
}
```

### 误区 3：忽略读取布局属性的代价

```javascript
// ❌ 在循环中读取布局属性
for (let i = 0; i < elements.length; i++) {
  elements[i].style.width = '100px';
  const height = elements[i].offsetHeight; // 每次都强制回流！
  elements[i].style.height = height + 'px';
}

// ✅ 批量读取
const heights = Array.from(elements).map(el => el.offsetHeight);
elements.forEach((el, i) => {
  el.style.width = '100px';
  el.style.height = heights[i] + 'px';
});
```

### 误区 4：认为 React/Vue 自动优化一切

```tsx
// ❌ React 不会阻止不必要的重渲染
function Parent() {
  const [count, setCount] = useState(0);

## 总结

### 🎯 核心要点回顾

#### 1. 回流 vs 重绘

```
回流（Reflow）：
- 重新计算布局和几何属性
- 成本高，影响范围广
- 触发条件：尺寸、位置、内容变化等

重绘（Repaint）：
- 重新绘制像素
- 成本较低，影响范围小
- 触发条件：颜色、可见性等视觉属性变化

性能排序：回流 >> 重绘 > 合成
```

#### 2. 优化原则

```
✅ 最小化回流次数
✅ 避免强制同步布局
✅ 优先使用 transform 和 opacity
✅ 批量 DOM 操作
✅ 使用虚拟滚动
✅ 合理运用 will-change
✅ 防抖节流高频事件
```

#### 3. 最佳实践清单

- [ ] 使用 CSS class 而非 inline styles
- [ ] 批量修改样式（cssText 或 class）
- [ ] 先读后写，避免读写交替
- [ ] 动画使用 transform/opacity
- [ ] 大列表使用虚拟滚动
- [ ] 图片使用懒加载
- [ ] resize/scroll 事件加防抖
- [ ] 使用 React.memo / useMemo 优化重渲染
- [ ] 定期用 Performance 面板检测性能
- [ ] 移动端特别关注回流优化

理想性能标准：

```
